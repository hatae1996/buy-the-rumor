# 기획 0.0.9 인수인계

`docs/questions.md` 76~83번의 답이다. 이번 꾸러미의 `docs/questions.md`에 답을 옮겨 두었다.

## 고칠 것 (0.0.9)

1. **시즌 길이 2주 (82)**
   - 시즌 = 13일 플레이 + 1일 결산·쉬는 날 = 2주. 격주 월요일 아침 9시(한국 시간)에 연다.
   - 게임 속 하루 2.5시간 그대로면 한 시즌은 게임 속 약 125일, 계절 하나 약 31일. 계절 길이, 보관 기간, 사건 수(시즌에 6~10개, 큰 주문 2~4번), 말 입고 간격, 벌이 목표의 "7일째"를 여기에 맞춘다.
   - 세계는 밤에도 쉬지 않고 돈다. 조용한 시간(기본 밤 11시~아침 8시)의 알림은 아침에 모아 보낸다.

2. **벌이 재는 법 (76)**
   - 모든 하루 벌이 목표는 판 것의 이익(판 값 − 산 값, 원정 산 값 0)으로 잰다. 7일째 20~40 그대로.
   - 첫 5일만 순자산(가진 것의 온값) 하루 증가로 재고 목표 5~10. 초반에 사 모아 두는 것은 좋은 장사라서다.

3. **행렬 (77)**: (가) + (나)
   - 행렬 수레를 수레방에서 빌릴 수 있게(하루 값, 돌려주면 끝). 사는 것도 그대로 가능.
   - 마부 일당은 길에 있는 날 12, 쉬는 날 4(초안).
   - 목표: 장사꾼 봇이 큰 주문 때 행렬을 꾸리는 판이 지금(40판 중 2판)보다 늘고, 꾸린 판이 평균적으로 이득.

4. **봄 구휼 사건 (78-나)**
   - 봄(보릿고개)에 영주가 곡물을 기준가 1.5배 안팎에 많이 사들이는 큰 주문 사건. 징조 소문 있음.
   - 목표: 여름 시작 시즌에서도 후반 평균 > 전반 평균.

5. **시간차 장사 (79)**: 그대로. 플레이어가 고르는 길, 봇 기본 성향은 하지 않음, 계절 값 차이는 키우지 않는다.

## 다음 큰 단계: 0.1.0 (81, 83)

0.0.9를 마치면 0.1.0으로 간다. 0.1.0은 혼자 하는 버전의 마무리이며 서버 없이 로컬에서 한다.

1. **여러 플레이어로 바꾸기:** `state.player` 하나를 여러 플레이어로. 장날 정산, 장부, 창고, 행렬, 말 선착순, 랭킹이 모두 여러 명을 다룬다. 플레이어 봇 20~50명이 한 시장을 나눠 쓰는 시험을 관찰 화면에서 돌린다. 재고 싶은 것: 경쟁할 때의 벌이, 상위 몇 명이 시장을 얼마나 차지하는지, 말 선착순, 세계당 알맞은 인원(기획서 "NPC 경제와 플레이어 수의 비율").
2. **예약 주문:** 하루 2~3번 접속하는 게임이라 서버 전에 꼭 있어야 한다(기획서 "시장").
3. **신문값:** 신문을 사서 전문을 본다(기획서 "소식을 얻는 방법").
4. **랭킹 화면과 시즌 결산:** 부문별 랭킹, 순자산 계산, 인장, 상인 증서, 시즌 리포트(기획서 "랭킹과 보상", 시안 `prototypes/id-card.html`).

0.2.0에 서버를 붙인다(80: Supabase 확정. Edge Function이 `src/sim`을 불러 하루를 돌리고, pg_cron이 부르고, 장날 정산은 Postgres 트랜잭션 하나로).

계속 보류: 은행 맡기기·빌리기, 소량 즉시 거래, 길드 의뢰(시즌 테마).
