# 기획 전달: 0.1.7 결과와 열린 질문 131~135 (2026-10-10)

0.1.7은 0.1.6 결과 전달의 답(질문 119~130)을 넣는 버전이었다. handoff 0.1.7의 일은 **모두 했다.** 문서 쪽(답 옮기기, `CLAUDE.md` 그림체 문구, 0.2.0 작업 목록)과 함께, 게임에 들어간 것은 셋이다.

1. **1일째 신문과 첫 5일:** 미리 돌린 마지막 날(0일) 시세로 1일째 신문을 찍고, 도시 시세 줄을 6개로 늘린 뒤 같은 측정으로 다시 쟀다. 12명 첫 5일 벌이는 6.5 → **6.8**이다. 보통 사람이 마이너스인 세계는 **1/20 그대로**다(다른 세계로 바뀌었다). 답 120 (라)대로 **판 이익으로 보면 도시에서 시작한 사람이 가장 낮다.**
2. **게임 시작 화면과 부품:** 견습 전에 **상단 이름 → 내 얼굴 → 문장**을 고르고, 모두 추천으로 채워져 "다음"만 세 번 누르면 된다. 증서에 얼굴·문장·상인 번호가 들어간다. 말에는 털색·무늬·이름이 생겼다. 부품 그림이 아직 없어 문장은 도형과 글자로, 말은 털색 점으로 그린다.
3. **그림 넣는 길:** 프롬프트대로 뽑은 문장·말 그림을 `assets-src/`에 넣고 `npm run parts`를 돌리면 바로 게임에 들어간다.

새로 생긴 질문은 다섯이고 모두 작다. 하나만 고르면 **133(12명 세계의 독점이 1 → 6/20으로 늘었다)** 이다. 나머지는 이름·번호·모양을 정하는 것이라 "그대로"로 넘겨도 된다.

"답:" 칸을 채워 주시면 다음 버전 작업 목록을 짠다. 개발 쪽 의견은 권하는 안일 뿐이고, 기획에서 다르게 정해도 된다. 그대로 좋으면 "그대로"라고만 적어도 된다.

함께 올릴 것: 이 문서 하나로 읽히게 썼다. 표 전체가 필요하면 `docs/확인목록-0.1.7.md`. 아이폰에서 본 뒤라면 **시작 화면 세 단계와 상인 증서 화면 캡처**를 같이 올리면 134·135와 시작 화면 목업을 정하기 쉽다.

## 만든 것

1. **답 119~130 옮기기, 그림체 문구.** `docs/questions.md` "답이 나온 질문" 표에 넣었다. `CLAUDE.md` "화면과 그림체"를 기획서와 같은 뜻으로 고쳤다: UI는 밝은 크림 바탕에 로우폴리 그림, 지도는 로우폴리(높이가 다른 육각 기둥, 면마다 한 색, 그림자), 툰 셰이딩과 외곽선 없음, 봄은 파스텔.
2. **1일째 신문, 도시 물품 6개, 다시 재기.**
   - 세계를 미리 돌린 마지막 날의 장 시세와 날씨로 **0일 신문**을 찍어 둔다. 미리 돌린 날의 큰 소식은 싣지 않는다(큰 소식 일정은 시즌과 함께 시작). 견습 마을 신문과 큰 소식 일정은 그대로.
   - 1일째에는 **도시에서 먼 마을도** 0일 신문을 판다. 그래서 사람도 봇도 1일째에 도시 값을 본다(측정에서 보통 사람과 장사꾼 봇 180자리가 모두 1일째에 샀다). 하루 늦게 오는 신문은 2일째부터다.
   - 졸업 선물 신문은 지금도 "방금 찍은 신문"이라, 1일째에 졸업하면 0일 신문이 된다(0.2.0 서버도 이것).
   - 화면에는 이 신문을 **"시즌 전날 신문"** 으로 적었다(질문 131).
   - 도시 시세 줄의 물품: 도시마다 그날 많이 거래된 것 4개 → **6개**. 그날 거래된 물품이 6개보다 적으면 있는 만큼.
   - **handoff에 없던 것 (봇 판단 고침):** 바꾼 뒤 혼자 돌린 보통 사람 봇 하나(시드 4242 가을 시작)가 시즌 끝에 손해(198 → 69)로 끝났다. 원인은 봇 판단이었다. 가져갈 마을에 닿았는데 가져온 물건은 이미 없고 다른 짐만 남아 있으면 "장사 계획"이 지워지지 않았다. 그래서 그 짐을 팔지도 옮기지도 않고 40일을 머물렀다. 계획한 물건이 짐에도 판매 신청에도 없으면 계획을 끝내게 고쳤다. 같은 판이 1223으로 끝난다. 게임 규칙은 그대로다.
   - 0.1.6과 같은 측정으로 다시 쟀다. 손수레 칸에 따른 곡물 거래는 새로 쟀다(답 127). 아래 "숫자".
3. **게임 시작 화면과 부품.**
   - **시작 화면:** 처음 하는 사람은 견습 전에 상단 이름 → 내 얼굴 → 문장을 지난다. 세 단계 모두 추천으로 채워져 있고, "추천"은 다시 뽑기, "‹ 이전"으로 돌아간다. 단계마다 노상인 한 줄("어서 오게, 젊은이. 장사를 하려면 상단 이름부터 있어야지. …"). 목업이 없어 0.1.6 크림 틀로 그렸다: 위에 1·2·3 단계 표시, 아래에 이전·추천·다음. 다음 시즌에는 묻지 않는다.
   - **상단 이름:** 추천은 봇 상단 이름 목록에서. 로컬은 글자 수(2~12)만 본다. **이름은 시즌 사이에만** 바꾼다. 시즌 중에는 증서에 안내 글만 있고, 결산 뒤에 이름 칸이 열린다. 결산 페이지에도 "상단 이름은 지금 바꿀 수 있어요" 한 줄을 넣었다.
   - **handoff에 없던 것 (이름 겹침):** 추천 이름과 봇 이름이 같은 목록에서 나와, 같은 세계의 봇이 내 상단과 같은 이름을 쓰는 일이 있었다. 같은 세계의 봇은 내 이름을 쓰지 않게 했다.
   - **상인 번호:** 증서 아래 "상인번호 000001"(0.1.6 목업 꼴, 여섯 자리). 로컬은 플레이어 1번, 봇은 2번부터(질문 132). 시즌을 넘어 그대로.
   - **내 얼굴:** 아바타 키트 그대로. 피부 3, 머리 3(지금 그림이 있는 것 모두, 남녀 구분 없이), 머리색 7(흰머리 포함), 상의 7, 옷 색 12, 수염(그림이 오면 고를 수 있다는 안내만). 옷 색은 상의의 주 색 영역 하나만 고르고, 셔츠·가죽·털 영역은 정해 둔 색이다. 추천은 늘 젊은 얼굴.
   - **문장:** 방패 모양 5, 바탕 색, 나눔 무늬 8, 무늬 색, 가운데 상징 10, 상징 색. 색은 게임 팔레트에서 10개(질문 134). 고르는 줄은 지금 문장에서 그 항목만 바꾼 작은 견본으로 보인다. 추천은 바탕 두 색의 밝기가 엇갈리고, 상징이 바탕에 묻히지 않게 뽑는다.
   - **그림이 오기 전:** 방패는 도형으로, 상징은 짧은 글자(밀·소금·말·열쇠·저울·배·생선·망치·뿔·돈)로 그린다. 그림이 생기면 방패는 그림 모양으로 자르고 명암을 곱한다. 상징은 그림 모양에 색을 칠하고 명암을 곱한다.
   - **보이는 곳:** 증서에는 얼굴(원형 사진)과 문장을 나란히 두었다(질문 135). 증서에서 "얼굴 바꾸기", "문장 바꾸기"로 언제든 바꾼다. 위 줄 왼쪽에는 0.1.6의 밀랍 봉인 대신 내 문장이 있다(누르면 증서). 랭킹의 내 세계 상단 이름 옆과 시즌 결산에도 얼굴·문장이 보이고, 남이 보는 증서도 같다. 지도는 지금처럼 말판.
   - **봇 상단의 문장:** 상징은 이름에 든 말로 고른다(은빛 송어 → 물고기, 구리 저울 → 저울, 녹슨 닻·푸른 돛 → 돛단배 …). 맞는 말이 없으면 시드로 고르고, 얼굴도 시드로 정한다.
   - **말:** 마구간에서 꺼내는 말마다 털색 5(밤색·갈색·검정·회색·크림)와 무늬 4(없음·이마 흰 줄·흰 발목·둘 다)를 세계 시드와 말 번호로 정한다. 기본 이름은 추천 목록 20개(밤톨, 바람, 구름 …)에서. 장부 "인력·말"과 마구간 "내 말"에서 **"이름 짓기"**(1~8글자, 비우면 처음 이름). 그림이 오기 전에는 점선 빈칸에 털색 점, 이름 아래 "짐말 · 회색 · 이마 흰 줄 · 흰 발목". 말은 시즌마다 초기화(그대로).
   - **예전 판:** 0.1.6 저장도 이어진다. 예전 문장(이름 하나)은 가까운 상징으로(닻 → 돛단배, 모루 → 망치 …) 바꾸고, 얼굴은 시드로, 상인 번호는 차례대로 채운다.
   - 남은 화면 문구 '금화'를 '골드'로 바꿨다(마구간 "골드 부족", 산적 길 "골드를 낸다" 등).
4. **문장·말 그림 빌드 (`npm run parts`).** 원본(1254×1254)을 넣고 돌리면 512 그림이 생기고, 화면이 바로 쓴다.
   - 문장: `assets-src/emblem/shield_heater.png` … `shield_oval.png`, `sym_wheat.png` … `sym_purse.png` → 회색조·투명 배경. 배경이 남아 있으면 모서리 색으로 지운다.
   - 말: `assets-src/horse/horse_pony.png`, `horse_draft.png`, `horse_riding.png` → 배경을 지운 몸 + 색 영역 지도(키트 `make_regions`: 털 1, 갈기·꼬리 2).
   - 무늬: `horse_<종류>_blaze.png`, `horse_<종류>_socks.png` → 원본 몸보다 밝고 흰 곳만 떼어 덮는다. 무늬 그림이 원본과 자리가 조금 어긋나면 무늬도 그만큼 어긋난다.
   - 가짜 그림(갈색 타원 말, 회색 방패)으로만 시험했다: 영역이 털·갈기로 나뉘고, 이마 흰 줄이 따로 뽑히고, 게임에서 회색·검정 말로 칠해졌다.
5. **확인 목록과 0.2.0 계획 고치기.** `docs/확인목록-0.1.7.md`, `docs/작업목록-0.2.0.md`(아래 "다음 버전에 바로 이어지는 것").

## 131. 1일째에 파는 0일 신문의 이름

**지금 게임은**
- handoff는 이 신문을 "1일째 신문"이라 불렀다. 그런데 게임의 신문 이름은 "그날 장날의 신문"이라, "1일째 신문"은 이미 1일 장날 뒤에 찍어 2일째에 파는 신문이다. 이름이 겹친다.
- 그래서 0일 신문은 화면에 **"시즌 전날 신문"** 으로 적었다. 신문 지면의 날짜 줄은 "시즌 전날 발행"이다.

**개발 쪽 의견:** 그대로. 시즌이 열리기 전날 장의 값이라는 뜻이 그대로 보인다.

**고를 수 있는 것**
- (가) 그대로("시즌 전날 신문").
- (나) 다른 이름(예: "개장 신문", "첫 신문").

## 132. 봇의 상인 번호

**지금 게임은**
- 상인 번호는 계정을 만든 순서이고, 로컬은 플레이어 1번이다(답 129).
- 로컬 게임의 봇 열하나에는 2~12번을 붙였다. 남이 보는 증서(랭킹에서 이름을 누르면 열린다)에 번호 줄이 비지 않게 하려는 것이다.
- 0.2.0 서버의 봇은 계정이 없다. 0.2.0 계획 9번에서 봇 상단에는 "떠돌이" 표시를 붙인다.

**개발 쪽 의견:** 로컬은 그대로, 서버 봇은 번호 없이 "떠돌이" 표시. 서버에서 봇에 번호를 주면 사람의 번호(계정 순서)와 섞인다.

**고를 수 있는 것**
- (가) 로컬은 그대로, 서버 봇은 번호 없이(추천).
- (나) 로컬 봇도 번호 없이(증서에 번호 줄이 빠진다).

## 133. 12명 세계의 독점이 1 → 6/20

**지금 게임은**
- 독점(답 92) = 같은 한 사람이 한 마을·한 물품에서 플레이어 판매의 50%를 넘은 날이 시즌의 절반을 넘은 세계 수.
- 1일째 신문과 신문 물품 6개를 넣고 다시 쟀더니 **12명이 1/20 → 6/20**으로 늘었다. 10명은 8 → 4, 15명은 4 → 3으로 줄었다.
- 0.1.6 때도 고치는 중간 단계마다 10명이 3, 3, 8로 흔들렸던 숫자다. 이번에 무엇 때문에 늘었는지(어느 마을·물품, 보통 사람인지 장사꾼 봇인지)는 따로 보지 않았다.

**개발 쪽 의견:** 고치지 않고, 0.2.0 비공개 테스트에서 사람 기준으로 다시 본다. 봇만으로 잰 숫자이고 작은 변화에도 크게 흔들려 왔으니, 사람 숫자가 더 쓸모 있다.

**고를 수 있는 것**
- (가) 그대로 두고 비공개 테스트에서 본다(추천).
- (나) 0.2.0 전에 원인을 판다: 늘어난 세계 다섯의 마을·물품·사람을 확인 목록에 적는다. 고치는 것은 원인을 보고 기획에서.
