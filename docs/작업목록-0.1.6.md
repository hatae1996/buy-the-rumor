## 2. 첫 5일: 봇 신문, 졸업 신문, 다시 재기

**한 일 (완료):**
- **신문의 도시 시세 줄에 값을 함께 둔다.** 지금까지 시세 줄은 글뿐이었다. 기사(`NewsItem`)에 도시(`town`)와 실린 값(`prices`)을 더했다. 글은 그대로다. 예전 저장의 기사에는 값이 없고, 봇은 그 기사를 건너뛴다.
- **봇은 도시 시세를 모르면 신문을 산다** (`src/sim/bot/paper.ts`). 도시에 가 본 적도, 신문에서 읽은 적도 없으면(또는 30일 넘게 지났으면) 신문팔이에게서 그날 신문을 산다(2냥). 실린 도시 시세를 봇 머릿속에 "아는 시세"로 둔다. 가 본 마을의 기억(모든 물품)에 신문 값(실린 물품만)을 얹어 "여기서 사서 어디에 팔지"를 고른다. 원정만 하는 봇은 사지 않는다.
- **신문이 오기를 기다린다.** 기획은 "첫날 신문"이지만, 1일째에는 신문이 없다. 신문은 장날 뒤에 나오고, 도시에서 하루 넘게 먼 마을에는 하루 늦게 온다. 그래서 신문은 도시 가까운 마을이 2일째, 먼 마을이 3일째에 처음 온다. 그런데 봇은 2일째에 이미 빈 수레로 도시를 둘러보러 떠났다. 사람처럼 **도시 시세를 모르고 이 마을에 신문이 아직 안 왔으면 둘러보러 떠나지 않고 기다리게** 했다. 원정이나 장사는 그대로 한다(질문 119).
- **사러 갈 마을을 고를 때도 여비를 센다(봇 고침).** 신문을 붙이니 혼자 돌린 장사꾼 하나(시드 8080)가 시즌 내내 4번만 거래하고 순자산 49로 끝났다. 원인은 이렇다. "어디서 사서 어디에 팔지" 정할 때는 가진 돈 전부로 셈했다. 그런데 살 마을에 닿으면 여비와 비상금을 남기느라 살 돈이 모자랐다. 그래서 두 마을 사이를 빈손으로 오갔다. 바꾸기 전에도 같은 일이 시드 99999 장사꾼에게 있었다(순자산 206). 고르는 셈도 여비와 비상금을 남기고 하게 맞췄다. 8080 장사꾼은 557(바꾸기 전 2793), 99999는 1838이 됐다.
- **견습 졸업 선물에 그날 신문 한 부.** 졸업은 첫 구매 장날 뒤에 오니, 방금 찍은 신문(다음 날 아침 "오늘 신문")을 안 읽은 신문으로 넣는다. 노상인 한 줄: "손수레와 길에서 먹을 식량, 그리고 오늘 신문을 주겠네. 가는 길에 읽어 보게. 도시 값이 실려 있지. …"
- 테스트(새로 5개, 고친 것 2개): 봇이 도시 시세를 모르면 신문이 나온 날 사고 실린 값을 기억한다, 알면 다시 사지 않는다, 원정만 하는 봇은 안 산다, 아는 시세 합치기, 예전 저장, 같은 시드 같은 결과, 시세 줄의 값이 글과 장 값과 같다, 졸업 선물 신문.
- **다시 쟀다.** 12명 기준, 10·15명 참고, 시드 5개 × 시작 계절 4개, 125일. 첫 5일 "판 이익"도 새로 쟀다. 결과는 `docs/확인목록-0.1.6.md` 2장. 측정 스크립트(`tests/nmarket.local.test.ts`, `tests/firstdays.local.test.ts`)는 이번에도 커밋하지 않았다.
- 한 줄로: **12명 첫 5일 4.7 → 6.5, 보통 사람이 마이너스인 세계 3 → 1.** 시즌 평균 18.4 → 17.5(목표 15~20 안). 도시에서 시작한 사람(16.8)은 아직 도시까지 2일(1.5)과 4일 이상(2.3) 묶음의 2배를 넘는다. handoff대로 알린다(질문 120).

## 4. NPC 외모: 아바타 키트

**한 일 (완료):** 0.1.4~0.1.5의 파츠 구조(앞뒤 머리, 얼굴·목, 눈썹·주근깨, 모자, 회색조 곱하기)와 자리표시 그림을 걷어 내고 키트 방식으로 바꿨다.
- **빌드 전 스크립트** `npm run portraits`(`scripts/portrait/build.py`, 키트의 `render.py`·`brows.py`를 불러 쓴다. 필요한 꾸러미는 `scripts/portrait/requirements.txt`). `assets-src/portrait/avatar-kit/`에서 `assets/portrait/`로 512 그림을 만든다.
  - 베이스: 배경을 투명하게, 피부 3 × (젊음 / 노인: 회색 눈썹 + 주름) = 6장.
  - 파츠: 본체와 `_mul`은 보통 줄이기, `_reg`는 nearest. 지금 키트의 파츠 10개(상의 7, 머리 3).
  - 그림 있는 파츠 목록을 `src/sim/looks/kitParts.ts`로 써 준다(자동 생성). 시뮬은 "목록에 있고 그림도 있는 파츠"만 뽑는다. 기획자가 새 파츠를 키트에 넣고 `npm run portraits`를 다시 돌리면 다음 빌드부터 쓰인다. `sources/`는 쓰지 않는다.
  - 게임용 그림은 모두 약 1.2MB. 다시 돌려도 바이트까지 같다.
- **외모(`Look`)**: 피부 3, 노인, 남자, 머리(모양·색), 상의(옷 색은 영역마다), 수염. 생김새(남녀, 피부, 나이, 머리, 수염)와 옷차림(상의, 옷 색)은 난수를 따로 써서, 그림이 새로 들어와도 다른 항목이 밀리지 않는다.
- **직업별 범위**: handoff 표대로. "top_13(없으면 top_05)"은 앞의 것이 없으면 뒤의 것. 수염은 남자만, 어부·대장장이·광부 50%, 도시 상인 30%, 나머지 15%, 색은 머리색. 노상인은 늘 노인·남자, `hair_03` 자주, `top_06`·`top_08`. 그 밖은 노인 25%.
- **남자 표시**(handoff에 없던 것): 얼굴이 하나라 남녀를 외모 값으로 둔다(시드로 50%). 여자만: `top_04`, `top_12`, `hair_05`, `hair_06`. 남자만: `hair_03`, `hair_04`, 수염. 누구나 쓰는 머리도 남자는 `hair_01`, 여자는 `hair_02`를 3배 자주 고른다(같은 비율이면 짧은 머리 여자가 남자로 보였다). 질문 121.
- **색 영역의 뜻**: 상의마다 영역 번호의 뜻이 달라(예: `top_04`는 1이 블라우스, 2가 조끼 원피스, `top_09`는 1이 가죽 조끼, 2가 셔츠) 파츠 목록에 영역마다 역할(직업 색, 셔츠, 가죽, 털, 머리색)을 적었다. 직업 색은 겉옷에, 셔츠·가죽·털은 따로 정한 색 목록에서. 아직 없는 상의 10~13은 "1번 = 직업 색"으로만 두었다.
- **화면**(`src/ui/portrait/`): 베이스 한 장 + 파츠마다 색 바꾸기(`regions.py`의 `recolor`를 TS로, 키트 값과 반올림 1 이내) → 그림자 곱하기 → 덮기. 곱하기와 덮기는 픽셀을 직접 계산한다(캔버스 multiply는 투명한 배경에 그림자를 칠한다). 256px 이하 초상은 256에서 겹쳐 줄인다. 다 그린 초상은 외모·크기마다 하나, 400개를 넘으면 오래된 것부터 버린다. 처음 36장을 그리는 데 0.7초.
- **겹침**: 얼굴이 하나라 조합이 겹치기 쉬워, 한 세계에서 겹치면 처음 12번은 옷만 다시 뽑는다. 그래서 일을 그대로 하는 일꾼도 앞 번호 일꾼이 일을 바꿔 옷이 겹치면 옷이 바뀔 수 있다(세 시드 14일: 90~100%가 옷까지 그대로, 생김새는 언제나 그대로). 예전 테스트 "같은 일이면 외모 전부 그대로"를 "생김새는 그대로, 옷까지 그대로가 80% 넘게"로 바꿨다. 질문 125.
- handoff 표에 없는 직업: 염전 일꾼(salter)과 표의 "염장꾼"(코드의 curer)은 농부 묶음, 장 상인(merchant)은 `top_08`·`top_03`·`top_04`에 꼭두서니·황토·쪽빛·올리브. 남자 여관 주인은 `top_10`이 올 때까지 `top_03`·`top_07`(`top_04`는 여자 옷). 질문 122.
- 머리 모양은 직업과 상관없이 고른다(노상인만 따로). 일꾼이 일을 바꿔도 얼굴이 그대로이게. 프롬프트 문서의 머리별 "쓰는 직업"은 반영하지 않았다. 질문 123.
- 관찰 화면 "NPC 얼굴 (아바타 키트)": 아직 그림이 없는 파츠 목록, 얼굴에 조합 툴팁.
- `assets-src/portrait/README.md`를 키트 방식으로 다시 썼고, `npc-prompts.md`에 "`npm run portraits`로 다시 만들고 커밋" 한 줄을 더했다.
- 테스트: `looks.test.ts`를 새 모델로 다시 썼고(직업 범위, 노상인, 수염은 남자만·머리색, 같은 시드 같은 얼굴, 한 세계 안 겹침, 그림 없는 파츠는 안 뽑힘), `portrait.test.ts`(색 바꾸기, Lab, 곱하기·덮기, 겹치는 순서)를 새로 붙였다.
