답을 옮긴 곳: `docs/questions.md` "답이 나온 질문"(131~135). 이 작업에서 생긴 질문은 136번부터 적는다.

## 목표

아이폰 사파리로 여는 **비공개 테스트(세계 2개 × 10~15명, 시즌 1번, 답 107)**를 서버 위에서 돌린다: 로그인 → 혼자 쓰는 견습 세계 → 졸업하면 공유 세계에 배정 → 명령 보내기 → 서버가 하루를 돌림 → 다시 열면 "자리를 비운 사이" → 시즌 결산과 시즌 전체 랭킹(두 세계 합산).
시뮬레이션 코드(`src/sim`)는 서버에서 그대로 부른다(구조 원칙 1~5를 지켜 온 이유). 시뮬에 더할 것은 견습 세계에서 공유 세계로 옮기기(7번)와 봇 표시(9번) 둘이다.

## 1. Supabase 프로젝트, 표 설계

- 표 (초안):
  - `seasons`: 시즌 id(여는 날 `2026-10-26` 꼴), 시드(`seasonSeed`), 여는 때, 끝나는 때, 상태(열림 / 결산 / 끝), **종류(예행연습 / 비공개 테스트 / 정식)**, **시험 시즌 표시**(게임을 망가뜨리는 버그로 접은 시즌: 랭킹·인장 없음). 마을 수는 늘 6곳이라 두지 않는다(답 105).
  - `worlds`: 세계 id, 시즌 id, 사람 수, 봇 수, 상태 JSON(`EconomyState`), 마지막으로 돌린 날, 버전(낙관적 잠금), **시뮬 버전**, 멈춤 이유(시뮬 버전이 다를 때 등). 맵은 시드로 다시 만든다(저장하지 않음).
  - `apprentice_worlds`: 계정마다 견습 세계 하나(상태 JSON, 시작한 때, 졸업한 때). 7번.
  - `members`: 계정 ↔ 세계 ↔ 플레이어 id(계정 id를 그대로 플레이어 id로: 시즌 전체 순위에서 id가 겹치지 않아야 한다, `ranking/table.ts`). 들어온 날.
  - `certificates`: 계정마다 상인 증서(상단 이름, **상인 번호**, **얼굴**, **문장**, 인장, 칭호, 연차). 시즌을 넘어 남는 것. 봇은 없다(봇은 세계 상태 안에만). 인장·칭호는 받은 시즌 id와 함께 두어, 정식 출시 때 시즌 종류로 지울 것을 가른다("개척 상인"과 상인 번호, 이름·얼굴·문장은 남김).
  - `score_rows`: 날마다 세계별 점수 줄(`ScoreRow`, 봇 표시 포함). 시즌 전체 순위는 사람 줄만 모아 매긴다.
  - `day_reports`: 플레이어마다 그날 요약(알림 거리, 장부 줄). "자리를 비운 사이"에 쓴다.
  - `commands`: 받은 명령 기록(시험과 부정 검사용, 상태를 다시 만들 수 있게).
  - `hall_of_fame`: 시즌마다 부문 1위(사람만).
  - `invite_codes`: 코드, 남은 사용 횟수, 메모. 여러 번 쓰는 코드 하나와 사람마다 코드 둘 다 이 표로 된다. 쓴 계정은 `accounts`(아래)에.
  - `accounts`: 계정 id(Supabase Auth), 상인 번호(시퀀스), 쓴 초대 코드, 가입 때, 마지막으로 들어온 때. 이메일은 Auth에만 둔다.
  - `banned_words`: 운영자가 더하는 금칙어(공개 목록은 번들 파일).
  - `feedback`: 계정, 글, 실제 시각, 게임 날(시즌·세계·날), 화면 이름. 사진 없음.
  - `play_events`: 계정, 종류(시작 화면 시작·끝, 견습 시작·졸업, 첫 거래 체결, 접속 시작, 접속 중 신호, 홈 화면 안내 봄 등), 실제 시각, 게임 날, 덧붙임 JSON. 신문·소문 적기·예약 주문·두 번째 행렬·말·고용은 `commands` 기록에서 센다(따로 보내지 않는다).
- 상태는 세계마다 JSON 하나로 둔다(1MB 안팎). 표로 쪼개지 않는다: 시뮬이 상태 전체를 한 번에 다루고, 정산은 세계 하나 안에서만 일어난다.
- 행 수준 보안(RLS): 폰은 `worlds`, `apprentice_worlds`를 직접 읽지 못한다. 화면 데이터는 서버 함수만 만든다(숨은 숫자가 폰에 오지 않게). 폰이 직접 쓰는 것은 내 `feedback`과 `play_events` 넣기뿐이다.
- 시간은 모두 한국 시간(Asia/Seoul)으로 계산한다. 저장은 `timestamptz`.

**한 일 (표 설계 완료, 프로젝트는 계정을 기다림):**
- `supabase/migrations/20261011000000_tables.sql`: 위 표 모두 + `season_results`(시즌마다 사람마다 순위·인장·칭호: 정식 출시 때 시즌 종류로 지우고 증서를 다시 만든다), `ops_log`(장날 멈춤 같은 운영 알림). 증서의 인장에 시즌 id를 넣는 대신 이 표로 가른다.
- **세계 상태는 `jsonb`가 아니라 `json`.** `jsonb`는 객체 키 순서를 바꾼다. 시뮬은 `Object.values`로 도는 곳이 있어(플레이어는 `seq`로 정렬하지만 물품 기록 같은 것은 아니다) 키 순서가 바뀌면 같은 시드·같은 명령의 같은 결과와 로컬·서버 상태 해시 비교가 깨질 수 있다.
- 묶음 규칙을 표에 걸었다: 세계는 사람 + 봇 15명까지, 한 시즌에 세계 하나(`members` 기본 키), 상단 이름은 띄어쓰기·기호를 걷어 낸 `name_key`가 유일(시즌 전체), 시즌 id는 여는 날 꼴, 의견은 1~2000자, 기록 사건은 정해진 종류만(`data`는 1000자까지).
- "첫 거래 체결"은 화면이 보내지 않고 서버가 장부에서 센다(`play_events` 종류에서 뺐다).
- RLS: 폰은 시즌 일정과 내 계정만 읽고, 내 이름으로 `feedback`·`play_events`만 넣는다. 나머지는 서버 키만.
- 테스트(`tests/db/schema.test.ts`, 12개): 마이그레이션을 PGlite(WASM Postgres, 새 개발 의존성 `@electric-sql/pglite`)에 Supabase의 `auth` 스키마·역할을 흉내 내어 올린다. 상인 번호 순서, 상태 키 순서 보존, 15명 상한, 같은 이름, 한 시즌 한 세계, 폰이 남의 표를 읽거나 고치지 못함, 남의 이름으로 의견을 넣지 못함. `npm test`에 들어가 GitHub 배포 전에도 돈다.
- 남은 것: Supabase 프로젝트를 만들면 `npx supabase init`(설정 파일)과 `link`, 마이그레이션 올리기. pg_cron은 3번 마이그레이션에서.

## 2. 시뮬을 서버에서 부르기

- `src/sim`을 Deno에서 불러올 수 있게 번들 하나로 묶는다(`npm run build:server`, Vite 라이브러리 빌드). Edge Function은 이 번들만 부른다.
- 서버 함수: `command`(명령 하나 적용 → 화면 데이터), `view`(화면 데이터), `tick`(세계 하루), `season`(열기·결산), `apprentice`(견습 세계 명령과 하루 보내기, 졸업).
- 같은 시드·같은 명령이면 같은 결과인지 서버와 로컬을 맞춰 보는 시험: 로컬에서 돌린 세계와 서버에서 돌린 세계의 상태 해시가 같다.

**한 일 (완료, 배포는 계정을 기다림):**
- **서버 입구 `src/sim/service/`** (순수 시뮬): `seasonMap`(시즌 id → 마을 6곳 지도), `openWorld`(사람 + 봇 n명, 미리 돌리기), `tickWorld`(봇 먼저, 그다음 장날, 점수 줄), `commandWorld`(사람 명령만, 봇 자리는 거절), `screenData`(`playerView` + `townFaces`), `stateHash`, `SIM_VERSION`. 표에 저장하는 것은 `WorldBlob` = 시뮬 버전 + `EconomyState` + **봇 머릿속(`crew`)**: 봇 판단 상태는 세계 상태 밖에 있어 함께 저장해야 같은 결과가 난다.
- **시뮬 버전**(3번을 당겨 옴): `SIM_VERSION = 1`. 세계의 버전과 번들의 버전이 다르면 `tickWorld`, `commandWorld`가 상태를 건드리지 않고 `SimVersionMismatch`를 던진다. 서버 함수가 이것을 받아 `worlds.halted`와 `ops_log`에 적는다(3번).
- **상인 번호**(답 132를 당겨 옴): `PlayerSpec.merchantNo`. 없으면 지금처럼 들어온 차례(로컬 1~12번), 서버는 사람에게 계정 번호, 봇에게 `null`.
- **번들**: `npm run build:server` → `supabase/functions/_shared/server.js`(Vite 라이브러리 빌드, ES 모듈 하나, 471KB, 줄이지 않음, 커밋하지 않음). 입구는 `src/server/index.ts`: 서버 쪽 일(표, 잠금, 시각)은 `src/server`에 TypeScript로 두고 우리 타입 검사·vitest·PGlite로 시험한다. Edge Function(`supabase/functions/*/index.ts`)은 번들을 불러 DB 연결만 넘기는 몇 줄로 둔다. 서버 함수 다섯(`command`, `view`, `tick`, `season`, `apprentice`)은 3~8번에서 이 모양으로 만든다.
- **`health` 함수**: 시뮬 버전과 짧은 판(3일)의 상태 해시를 돌려준다. 배포한 뒤 로컬 값과 같으면 배포한 번들이 소스와 같은 규칙으로 돈다. 로컬 Deno로 띄워 응답을 확인했다.
- **같은 결과 시험:**
  - `src/sim/service/service.test.ts`(11개): 날마다 JSON으로 저장했다 읽는 서버 방식과 메모리에서 이어 돌린 로컬 방식이 8일 동안 해시가 같다, 같은 시즌 세계 둘은 세계 id(세계와 플레이어 시즌 기록)만 다르다, 봇은 번호 없음, 봇 이름은 사람 이름과 안 겹침, 버전이 다르면 상태를 건드리지 않음.
  - `npm run test:deno`(`tests/server/parity.deno.ts`): 번들을 만들고 Deno 2.9에서 6일을 돌려, Node에서 소스로 돌린 해시와 날마다 같은지. Deno가 없는 GitHub 배포에서는 돌지 않게 `npm test`에서 뺐다.
- **잰 값** (Node, 12명·마을 6곳, 125일 시즌): 지도 25ms, 세계 열기(미리 돌리기 20일) 77ms, 장날 하루 16~40ms(봇 판단 포함), JSON 저장·읽기 1~11ms, 상태 59KB(1일) → 374KB(30일) → 839KB(125일), 명령 + 화면 데이터 1~2ms. Edge Function의 요청당 CPU 한도(약 2초) 안에 세계 여럿을 한 번에 돌려도 넉넉하다.

## 3. 하루 돌리기

- 하루 = 실제 2시간 30분(지금 로컬과 같다, `DAY_MS`). pg_cron이 `tick`을 부르고, 세계마다 `advanceDay` 한 번(봇이 있는 세계는 봇 판단 `crewDay` 먼저). 밤에도 돈다(확정, 0.0.9).
- 명령과 장날이 겹치지 않게 세계마다 잠근다(행 잠금 또는 버전 비교). 장날이 도는 동안 온 명령은 다음 날 신청으로 받는다.
- 늦어지거나 빠진 장날은 다음 `tick`이 밀린 날만큼 돌린다(로컬의 `catchUp`과 같은 방식).
- 하루를 돌린 뒤 점수 줄(`scoreRows`)과 플레이어별 요약을 표에 남긴다.
- 견습 세계는 돌리지 않는다(견습은 "하루 보내기"로만 날이 간다, 7번).
- **시뮬 버전**(handoff 3번): 시뮬에 `SIM_VERSION` 상수를 두고 세계 상태에 적는다. 시뮬 규칙이나 숫자를 바꾸면 올린다(화면·글·그림만 바꾸면 그대로). `tick`은 번들의 버전과 세계의 버전이 다르면 그 세계의 장날을 돌리지 않고 멈춤 이유를 적고 운영자에게 알린다. 시즌 중에는 시뮬 규칙과 숫자를 바꾸지 않는다(같은 시즌 세계가 같은 규칙이어야 랭킹을 합친다). 상태를 바꾸지 않는 시뮬 버그 고침은 버전을 올리지 않는다.
- 장날 시각은 시즌 여는 때(격주 월요일 아침 9시, 한국 시간)부터 2시간 30분마다.

**한 일 (완료, pg_cron이 실제로 부르는 것은 프로젝트를 만든 뒤):**
- **부르는 간격**: 장날 시각에 맞춰 부르지 않고 **pg_cron이 5분마다** `tick`을 부른다(`supabase/migrations/20261011010000_tick_cron.sql`, pg_net으로 Edge Function 호출, 주소와 비밀 값은 Vault). `tick`은 시즌 여는 때부터 열렸어야 할 장날 수를 세어(`src/server/schedule.ts`) 밀린 날만 돌린다. 장날은 많아야 5분 늦고, 빠지거나 겹친 호출도 같은 결과가 된다. 첫 장날은 여는 때 + 2시간 30분, 13일이면 장날 124번(시즌 125일째 장날은 14일째 새벽).
- **`tickDue`**(`src/server/tick.ts`): 세계마다 트랜잭션 하나. `select … for update skip locked`로 행을 잠그고(다른 tick이 잡고 있으면 건너뜀) 상태를 읽어 봇 → 장날을 밀린 날만큼, 다시 쓰고 `rev`를 올린다. 명령(5번)도 같은 행을 잠그므로 장날이 도는 동안 온 명령은 끝난 뒤 다음 날 신청으로 들어간다.
  - 한 세계를 한 번에 20일까지만 돌리고 나머지는 다음 호출에(오래 멈췄다 다시 돌 때 요청 CPU 한도 안에).
  - 장날마다 점수 줄(`score_rows`, 봇 표시는 지금은 봇 머릿속 목록으로, 9번에서 시뮬 표시로)과 사람마다 그날 요약(`day_reports`: 들은 소문, 도장, 알림 거리)을 남긴다.
  - 시뮬 버전이 다르면 상태를 건드리지 않고 `worlds.halted`와 `ops_log`에 남긴다. 멈춘 세계는 다음 호출에도 돌리지 않는다(운영자가 풀어 준다).
  - 한 세계가 실패하면(상태가 깨짐 등) 그 세계만 되돌리고 `ops_log`에 적고 다른 세계는 돈다.
  - 세계가 마지막 장날을 마치면 `worlds.settled`(표에 새 칸), 시즌의 세계가 모두 끝나면 시즌을 `settling`으로(결산은 10번).
- **Edge Function `tick`**: 비밀 값(`TICK_SECRET`)으로 막고 JWT 검사를 끈다. DB는 postgres.js(`supabase/functions/_shared/pg.ts`, `SUPABASE_DB_URL`). Edge Function 쪽 npm 패키지는 `supabase/functions/deno.json`으로 Deno 캐시에서 받는다(저장소의 node_modules를 보지 않게).
- **찾은 함정**: postgres.js는 `$1::json` 자리에 넘긴 글자열을 한 번 더 JSON으로 감싸 **세계 상태가 글자 하나로 저장된다**. PGlite 시험에서는 드러나지 않아 Deno 끝까지 시험에서 잡았다. JSON은 `$1::text::json`으로 넘긴다(`src/server/db.ts`에 적음).
- **시험**:
  - `tests/server/tick.test.ts`(PGlite, 10개): 하루 길이가 로컬과 같다, 열리기 전에는 안 돈다, 밀린 3일을 돌리면 로컬에서 같은 세계를 3일 돌린 것과 해시가 같다, 점수 줄·그날 요약, 같은 때 다시 불러도 안 돈다, 20일 상한과 이어 돌기, 세계 둘이 따로, 버전이 다르면 멈춤·로그·상태 그대로, 깨진 세계만 실패, 모든 세계가 끝나면 시즌 결산으로.
  - `tests/server/tick.deno.ts`(`npm run test:deno`): `tick` 함수를 Deno로 띄우고 postgres.js로 PGlite 소켓(`@electric-sql/pglite-socket`, 새 개발 의존성)에 붙여, 비밀 값 없으면 403, 밀린 장날 4번을 돌려 표에 남기는지, 상태가 객체로 저장되는지.
  - DB 시험 준비는 `tests/db/pglite.ts`로 모았다(첫 줄 `pglite: skip`인 마이그레이션은 건너뜀).
- 운영자가 할 일(프로젝트를 만든 뒤)은 `supabase/README.md`에: 로그인·잇기, `db push`, `TICK_SECRET`과 Vault 값, 함수 올리기, `health`로 해시 맞추기.

## 4. 로그인과 계정

- Supabase Auth: **구글 계정과 이메일 링크**(답 109). 애플 로그인은 앱(Capacitor) 출시 때.
- **초대 코드**(handoff 1번): 로그인한 뒤 계정이 없으면 "초대 코드를 넣어 주세요"에서 멈춘다. 서버가 코드의 남은 횟수를 줄이고 계정(`accounts`)과 상인 번호를 만든다. 코드는 운영자가 스크립트로 만든다.
- 처음 들어오면 **게임 시작 화면**(상단 이름 → 얼굴 → 문장, 답 129)을 지나 견습 세계를 연다(7번). 세 값은 `certificates`에 계정과 함께 저장하고, 다음 시즌에는 묻지 않는다.
- **상인 번호**: 계정을 만든 순서. 서버가 붙인다(시퀀스). 시즌을 넘어 그대로. 로컬 게임은 1번(0.1.7).
- 상단 이름은 서버가 받을 때 **금칙어를 걸러 낸다**: 공개된 한국어 욕설 목록(라이선스 확인, handoff 7번) + 운영자 목록(`banned_words`). 띄어쓰기·기호 섞기도 잡는다. **같은 상단 이름은 시즌 전체(모든 세계)에서 한 사람만**: 이름은 증서에 계정마다 하나라, 정규화한 이름에 유일 색인을 건다. 봇 이름(`BOT_COMPANY_NAMES`)은 사람이 가진 이름을 빼고 뽑는다(로컬과 같게). 이름은 시즌 사이에만 바꾼다(시뮬은 `setCompany`를 결산 뒤에만 받는다, 0.1.7). 얼굴과 문장은 언제든.
- 얼굴과 문장은 고를 수 있는 값인지 시뮬 함수로 검사한다(`setFace`, `setEmblem`). 그림 없는 파츠는 받지 않는다.

**한 일 (서버 쪽 완료, 로그인 화면은 11번, 구글·이메일 설정은 프로젝트를 만든 뒤):**
- **`account` 함수**(`src/server/account.ts`, 껍데기 `supabase/functions/account`): `me`(내 계정, 없으면 `noAccount` → 초대 코드 화면), `redeem`(초대 코드), `checkName`(시작 화면 1단계에서 그 자리에서), `found`(상단 이름 → 얼굴 → 문장으로 증서, 한 번만), `setLook`(얼굴·문장은 언제든).
  - 초대 코드: 하이픈·빈칸·소문자를 걷어 견준다. 다시 눌러도 코드를 또 쓰지 않는다(이미 계정이면 그 계정). 없는 코드와 다 쓴 코드를 나눠 알린다. 계정을 만들 때 상인 번호(시퀀스)를 붙인다.
  - 운영자 SQL 함수 `make_invite_codes(n, 횟수, 메모)`(`supabase/migrations/20261011020000_invite_codes.sql`): 헷갈리는 글자를 뺀 8자, 폰에서는 못 부른다.
  - 같은 이름: 띄어쓰기·기호·대소문자·전각을 걷어 낸 꼴(`nameKey`)에 유일 색인. 같은 때 같은 이름을 넣은 두 사람은 색인이 하나만 받는다. 증서가 시즌을 넘어 남으므로 실제로는 시즌 전체보다 넓게(지금 증서를 가진 모든 사람과) 겹치지 않는다.
  - 금칙어(`src/server/names.ts`, `bannedWords.ts`): 이름과 금칙어를 같은 꼴로 바꾸고, 숫자를 뺀 꼴도 견준다("시1발"). NFKC가 자음 글자(ㅅ)를 첫가끝 자모로 바꾸는 것까지 남겨 "ㅅㅂ"도 잡는다. 외부 목록은 질문 136.
  - 이름 바꾸기(시즌 사이에만)는 10번 결산에서.
- **로그인 확인**: Supabase 문서대로 플랫폼의 JWT 검사(`verify_jwt`)를 켜 두고, 함수 안에서 `@supabase/server@1.7.2`의 `withSupabase({ auth: 'user' })`가 JWKS로 한 번 더 확인해 계정 id를 준다. CORS 미리 묻기도 이것이 답한다.
- **시험**:
  - `src/server/names.test.ts`(21개): 막는 이름(띄어쓰기·숫자·기호·전각·자음·영문), 막지 않는 이름(새끼 고양이, 시바견, 대한남부, 신발, 십자성), 운영자 목록.
  - `tests/server/account.test.ts`(PGlite, 13개): 코드 없이 멈춤, 상인 번호 순서, 다시 눌러도 한 번, 없는·다 쓴 코드, 운영자 함수, 증서 만들기, 한 번만, 같은 이름, 금칙어와 운영자 목록, 글자 수·얼굴·문장, 실패하면 아무것도 안 남음, 얼굴·문장 바꾸기, 요청 나누기와 400.
  - `tests/server/account.deno.ts`(`npm run test:deno`): `account`를 Deno로 띄우고 시험 안에서 만든 ES256 키를 JWKS로 넘겨, 로그인 없음·다른 키·만료된 토큰은 401, CORS 미리 묻기, 초대 코드 → 상단 세우기 → 내 계정이 postgres.js로 표에 들어가는지.
- 운영자 설정(로그인 주소, 이메일·구글, 초대 코드, 금칙어, 계정 지우기)은 `supabase/README.md`.

## 5. 명령 받기와 화면 데이터

- 폰은 명령(`Command`)만 보내고, 서버가 `applyCommand` → 상태 저장 → `playerView` + `townFaces`를 돌려준다. 실패는 지금처럼 오류 이름으로.
- 원정 카드처럼 난수가 드는 명령도 서버에서만 정한다(지금도 시뮬 안 시드 난수라 그대로).
- 얼굴은 시즌 id(`seasonSeed`)와 그 세계의 NPC 명단으로 정해진다. 같은 시즌의 세계 둘에서 같은 소문꾼·여관 주인은 같은 얼굴이다(0.1.4 테스트로 고정).

**한 일 (서버 쪽 완료, 폰 쪽 서버 게임은 11번):**
- **`game` 함수**(`src/server/game.ts`, 껍데기 `supabase/functions/game`): `view`(화면 데이터, 잠그지 않고 읽음), `command`(명령 하나). 지금 들어가 있는 세계는 끝나지 않은 시즌의 `members`에서 찾고, 없으면 `noWorld`(견습 중이거나 배정을 기다림, 7·8번).
  - 명령은 세계 행을 잠그고(`for update`, 장날 tick과 같은 잠금: tick이 도는 동안 온 명령은 기다렸다가 다음 날 신청이 된다) 적용, 성공하면 저장하고 `rev`를 올린다. 실패하면 상태를 건드리지 않는다. 성공·실패 모두 `commands` 표에(실패는 오류 이름과 함께).
  - 돌려주는 것은 `playerView` + `townFaces` + 시즌·세계 id + 멈춤 이유뿐(숨은 숫자 없음). 실패해도 새 화면을 같이 준다.
  - 멈춘 세계(`halted`)는 화면은 보이고 명령은 `worldHalted`.
  - 증서를 바꾸는 명령(이름, 얼굴, 문장, 인장 달기, 칭호)은 `certificates` 표에도 옮긴다. 세계에 든 동안 얼굴·문장은 이 명령으로 바꾼다(`account`의 `setLook`은 세계 밖에서).
  - 남에게 보이는 글자는 서버가 먼저 거른다: **말 이름**의 금칙어(새로 찾음, 0.1.7 말 이름), 상단 이름(시즌 사이)의 금칙어와 같은 이름. 글자 수는 시뮬이 본다.
  - 명령 모양이 아니거나 20,000자를 넘으면 400.
- **시뮬 고침**: `applyCommand`가 모르는 명령(`type`이 없거나 없는 이름)에 `badCommand` 실패를 돌려준다. 전에는 switch에 기본 갈래가 없어 서버에서 함수가 터졌다. 상태를 바꾸지 않는 고침이라 시뮬 버전은 그대로. 화면 문구도 더했다.
- 시즌 지도는 함수 인스턴스가 살아 있는 동안 시즌마다 한 번만 만든다(`src/server/maps.ts`, tick과 같이 씀).
- **잰 값**(PGlite, 15명·111일째, 상태 964KB): 명령 하나 중앙값 34ms(읽기·적용·쓰기·기록), 화면 데이터 9ms, 폰에 가는 화면 데이터 18KB. 명령마다 상태 전체를 다시 쓰므로, 한 세계의 명령은 1초에 30개쯤이 한도다. 비공개 테스트(세계당 15명)에는 넉넉하고, 더 커지면 하루 신청을 따로 쌓는 방식을 본다.
- **시험**:
  - `tests/server/game.test.ts`(PGlite, 8개): 화면 데이터에 숨은 숫자 없음, 세계 없는 사람, 성공한 명령이 로컬에서 같은 명령을 낸 것과 같은 상태, 실패한 명령은 상태 그대로·이유 기록, 모르는 명령과 400, 멈춘 세계, 증서 표에 옮기기, 말 이름 금칙어·남의 상단 이름·시즌 중 이름 바꾸기.
  - `tests/server/game.deno.ts`(`npm run test:deno`): `game`을 Deno로 띄워 로그인 없으면 401, 화면 데이터, 명령 저장·기록, 400.
  - Deno 끝까지 시험의 준비(PGlite 소켓, 함수 띄우기, 토큰 서명)는 `tests/server/denoHarness.ts`로 모았다.

## 6. 자리를 비운 사이와 화면 안 알림

- 로컬은 지나간 날을 그 자리에서 돌리며 요약을 만든다(`Game.catchUp`). 서버는 날마다 플레이어별 요약(`dayNotices`, 장부 줄, 들은 소문, 도장)을 남겨 두고, 다시 열면 마지막으로 본 날부터 모아 보낸다.
- 알림은 **화면 안 알림만**(답 110): 앱을 열었을 때 쌓인 알림, 열어 둔 동안 장날이 지나면 화면 위 띠. 웹 푸시는 하지 않는다(앱 출시 때).
- 조용한 시간(밤 11시~아침 8시, 한국 시간)에 생긴 알림은 띠로 띄우지 않고 다음에 열 때 모아 보여 준다(handoff 8번, 시뮬의 `planDelivery`가 이미 `later`로 나눈다).

**한 일 (서버 쪽 완료, 폰에서 띠와 쪽지를 보이는 것은 11번):**
- **로컬과 서버가 같은 함수**(`src/sim/service/away.ts`): 장날마다 사람마다 하루치 기록(`PlayerDigest`: 들은 소문, 도장, 알림 거리, 그 장날에 새로 생긴 장부 줄, 도착한 마을)을 만들고, `awaySummary`가 모아 "자리를 비운 사이"(`AwaySummary`)를 만든다. `tickWorld(blob, map, watch)`가 지켜볼 사람의 하루치 기록을 돌려준다.
  - 로컬 `Game`도 이제 `tickWorld`와 `awaySummary`로 날을 넘긴다(`AwaySummary` 모양은 그대로, `src/ui/game.ts`가 다시 내보냄). 브라우저에서 "시험용: 장날 열기"로 쪽지가 전처럼 뜨는 것을 확인했다.
  - 장부는 "장날을 돌리는 동안 새로 생긴 줄"만(로컬이 하던 대로). 서버가 장부를 날짜로 거르면 그날 낮에 내가 한 일까지 들어가서, 장날 전후 길이로 잘랐다.
- **서버**: tick이 장날마다 사람의 하루치 기록을 `day_reports`에 둔다. `game`의 `view`가 마지막으로 본 날(`members.seen_day`)부터 모아 `away`를 붙인다(돌린 장날이 없으면 null). 폰은 보여 준 뒤 `seen`(본 날)을 보낸다: 본 날은 내려가지 않고 세계의 오늘을 넘지 않는다. tick 여러 번에 걸친 날도 한 번에 모인다.
- **화면 안 알림**: `away.delivery`는 시뮬의 `planDelivery`를 그 사람의 알림 설정과 **한국 시간**(`kstHour`, 서머타임 없음)으로 돌린 것. 낮에는 `send`(띠로), 조용한 시간(기본 밤 11시~아침 8시)에는 `later`(띠 없이 요약에만), 하루 상한을 넘은 것은 `toSummary`. 켜 둔 종류만.
- **시험**:
  - `tests/server/away.test.ts`(PGlite, 7개): 장날이 안 지났으면 없음, 서버 요약이 로컬에서 같은 날을 돌린 요약과 같다(3일, tick 세 번에 걸친 12일), 본 날을 올리면 그 뒤만, 본 날의 위아래 한도, 한국 시간, 낮·밤 알림 나누기.
  - `tests/server/game.deno.ts`에 `view`의 `away`와 `seen`을 더했다.

## 7. 견습 세계 (답 111)

- 견습은 공유 세계 밖의 **혼자 쓰는 작은 세계**에서 한다. 견습 마을 하나와 그 둘레만 쓰고, 날은 "하루 보내기"로만 간다(지금처럼). 길어도 한두 시간 안에 끝나는 장면 수와 날 수인지 잰다.
- 시뮬에 더할 것:
  - 견습 세계 만들기: 그 시즌 시드와 견습 마을로 작은 세계(사람 한 명, 봇 없음). 지금 견습 장면(`src/sim/apprentice`)을 그대로 쓴다.
  - 졸업 짐 꾸리기: 견습 세계에서 **돈, 짐, 손수레, 여행 식량**만 꺼낸다. 시세 기억, 소문 수첩, 신문, 장부는 가져가지 않는다.
  - 졸업 선물 신문(답 116): 들어갈 **공유 세계의 그날 신문** 한 부를 넣어 준다(안 읽은 신문). 로컬은 0.1.6에서 견습 마을이 공유 세계 안이라 그 세계의 신문을 준다(`graduationGift`). 서버는 공유 세계에 들이는 함수가 그 세계 신문 날짜를 넣는다. **1일째에 졸업하면 0일 신문**(답 119, 미리 돌린 마지막 날 시세).
  - 공유 세계에 들이기: 그날의 공유 세계에 플레이어 한 명을 더한다(시작 마을은 지금 규칙대로, 짐과 손수레를 실어서). 지금 시뮬은 세계를 만들 때만 플레이어를 받으므로 이 함수가 새로 든다. 시즌 중간 참가(8번)도 이것을 쓴다.
- 테스트: 견습 세계의 시세·소문이 공유 세계로 넘어오지 않는다, 졸업 짐이 그대로 들어온다, 들어온 뒤 하루가 같은 시드 규칙으로 돈다.

**한 일 (서버 쪽 완료, 화면은 11번):**
- **시뮬 `joinPlayer`**(`src/sim/economy/join.ts`): 시즌 중간에 세계에 한 사람을 앉힌다. 들어온 차례(seq)를 이어서 매기고, 같은 모양의 플레이어를 만들고, 시즌 기록은 들어온 날부터 연다. 들고 온 것(`JoinKit`: 돈, 수레와 그 안의 짐·여행 식량, 열린 화면, 알림 설정)을 싣는다. 짐 신선도는 날 번호가 아니라 상한 정도라 다른 세계로 옮겨도 그대로이고, 수레 조각 번호는 수레마다라 겹치지 않는다. 견습 세계의 장 신청 자리는 비운다. 8번의 봇 채우기도 이것을 쓴다.
- **견습 세계**(`src/sim/service/apprentice.ts`): 같은 시즌 시드·같은 미리 돌리기로 연 세계에 사람 한 명, 봇 없음. 그래서 지도·마을·시세가 공유 세계의 시작과 같다. 날은 "하루 보내기"로만 간다(tick이 돌리지 않는다).
  - 졸업: 졸업 장면에서 처음 길을 떠나는 명령(`travel`, 로컬에서 견습이 끝나는 바로 그 명령)이 오면, 돈·수레(짐, 여행 식량)·열린 화면·알림 설정만 들고 **그날의 공유 세계 견습 마을**에 앉히고 그 길을 떠나게 한다. 시세 기억·소문 수첩·신문·장부는 두고 온다.
  - 선물 신문: 공유 세계에서 가장 최근에 찍은 신문 한 부(안 읽음). 1일째 장날 전이면 시즌 전날(0일) 신문(답 116·119).
  - 첫 신문의 조선소 소식: 견습 세계에서 일으킨 조선소 사건을 공유 세계의 그 마을에도 일으킨다(그 마을에 이미 있으면 그대로). 로컬에서는 견습이 공유 세계 안이라 원래 그랬다. 졸업하는 사람마다 생길 수 있어 질문 137.
  - 일곱 장면은 장날 두 번(하루 보내기 두 번)으로 끝난다: 한두 시간 안.
- **서버**(`src/server/apprentice.ts`, `game` 함수에 더함): 공유 세계에 들기 전에는 견습 세계가 화면과 명령을 받는다(화면 데이터에 `place: 'apprentice' | 'world'`).
  - `startApprentice`: 상단을 세운 뒤, 열린 시즌의 견습 세계를 연다(다시 눌러도 같은 것). 없으면 `noSeason`, 상단이 없으면 `notFounded`, 이미 세계에 들었으면 `alreadyInWorld`.
  - `passDay`: 견습의 하루 보내기, 지난 하루의 요약을 돌려준다.
  - 명령: 견습 세계 행을 잠그고 적용, 기록은 세계 id 없이. 졸업 명령이면 들어갈 세계를 잠그고 앉히고 `members`(들어온 날 = 본 날 = 그 세계의 오늘), 세계 사람 수, 견습 졸업 시각을 남기고 공유 세계 화면을 돌려준다.
  - 들어갈 세계: 지금은 "사람이 가장 적고 사람 + 봇이 15명이 안 된 세계". 모두 찼으면 `worldsFull`(졸업 장면에서 기다림). 1일 장날 전후 규칙, 10일째 마감, 봇 채우기는 8번.

## 8. 시즌 열기, 세계 배정, 봇으로 채우기

- 시즌 여는 날 시즌 하나(시드 = `seasonSeed(시즌 id)`)를 만든다. 세계는 모두 **마을 6곳, 같은 지도**(답 104·105).
- **시즌 1일 장날 전**(답 115): 견습을 마친 사람을 공유 세계 중 **사람(봇 빼고)이 가장 적고 15명이 안 된 세계**에 넣는다. 모든 세계가 15명이면 **새 세계를 연다**: 같은 시즌 시드, 같은 마을 6곳 지도. 아직 1일이라 미리 돌리기(20일)만 하면 같은 날이다.
- **봇으로 채우기**(답 108, 112, 115): **1일 장날 직전에** 사람이 12명이 안 되는 세계만 봇 상단으로 12명까지 채운다(벌이 목표 기준 인원). **봇은 시즌 중에 빠지지 않고**, 15명 상한에 함께 센다(답 114). 봇이 가진 짐과 장 신청이 사라지면 장이 흔들리기 때문이다.
- **시즌 중간**(2~10일째): 사람이 가장 적고 봇을 합쳐 15명이 안 된 세계에. **모든 세계가 차 있으면 새 세계를 열지 않고 "다음 시즌을 기다려 주세요"**(답 115). 새 세계를 1일부터 오늘까지 따라잡게 돌리는 것은 나중 버전.
- 시뮬에 더할 것: 봇 n명을 세계에 더하는 함수(7번의 "공유 세계에 들이기"와 같은 것, 봇 이름은 `BOT_COMPANY_NAMES`). 테스트: 사람 수 → 봇 수(0~11명 → 12명까지, 12명 이상 → 0), 1일 장날 전에는 봇을 넣지 않는다, 봇은 날이 가도 그대로, 배정은 사람이 가장 적은 세계, 15명 세계에는 안 넣음, 1일 전에 모두 차면 새 세계(같은 지도), 시즌 중간에 모두 차면 기다림.
- 비공개 테스트(세계 2개 × 10~15명, 답 107)는 "사람이 적은 세계부터" 규칙만으로는 한 세계가 15명이 찬 뒤에야 둘째 세계가 열린다. 테스트 때는 운영자가 시즌을 열 때 세계 둘을 미리 연다(handoff 1번 확정). 시즌 열기 스크립트에 "세계 n개 미리 열기"를 둔다.
- 시즌 중간 참가는 10일째까지(기획서 초안). 견습을 마친 날이 11일째부터면 다음 시즌까지 기다린다(그때 어떻게 보여 줄지는 화면 작업에서).

**한 일 (서버 쪽 완료, 기다리는 화면은 11번):**
- **시즌 열기**(`src/server/season.ts`, 운영자 함수 `admin`): 시즌 id = 여는 날(한국 시간), 아침 9시에 열고 2주 뒤 닫는다. 예행연습이 아니면 월요일이어야 한다. 빈 세계를 미리 n개(비공개 테스트는 둘) 연다: 같은 시즌 시드, 마을 6곳, 미리 돌리기를 마친 1일째, 사람도 봇도 없다. 세계 id는 `w1`, `w2`, ….
  - `admin` 함수: `openSeason`, `addWorld`. 비밀 값(`ADMIN_SECRET`)으로 막고 JWT 검사를 끈다. 쓰는 법은 `supabase/README.md` "시즌 열기".
- **들어갈 세계 고르기**(`pickWorld`, 7번 졸업이 부른다):

  - 첫 장날 뒤: 자리가 남은 세계에만. 모두 찼으면 `worldsFull`("다음 시즌을 기다려 주세요", 답 115).

- **봇으로 12명 채우기**(시뮬 `fillBots`, tick이 부름): 세계의 **첫 장날 직전에** 사람 + 봇이 12명이 안 되면 봇으로 12명까지. 이미 봇이 있으면 다시 채우지 않는다(시즌 중에 빠지지도 않는다). 봇은 시뮬 `joinPlayer`로 앉는다: 시작 마을은 들어온 차례로 랜덤(`seededStartTown`, 세계를 만들 때 봇과 같은 규칙), 손수레, 상인 번호 없음, 이 세계 사람과 다른 이름. 말 입고 일정은 첫 장날 아침의 인원(사람 + 봇)으로 짠다(이미 그랬다). `worlds.bots`를 같이 적는다.

## 9. 봇 상단 표시 (답 108)

- 시뮬: 플레이어에 봇 표시(지금은 봇 id 규칙으로만 안다)를 두고, 점수 줄(`ScoreRow`)에 봇 표시를 붙인다. 시즌 전체 순위, 인장, 칭호, 상위 10%, 5명 문턱, 명예의 전당은 사람 줄만 센다. 내 세계 순위에는 봇도 그대로 보인다.
- 화면: 봇 상단 이름이 보이는 곳(내 세계 순위, 상인 증서, 신문 큰손 기사, 지도의 말)에 작은 "떠돌이" 표시. 사람인 척하지 않는다.
- 로컬 게임(나 + 봇 11, 답 117)에도 같이 쓴다: 지금 로컬 봇은 인장과 칭호를 받는다.
- 상인 번호(답 132): 로컬 봇은 그대로 2~12번. 서버 봇은 계정이 없어 번호 없이 "떠돌이".

## 10. 시즌 전체 랭킹과 결산

- 장날마다: 세계를 다 돌린 뒤 `score_rows`를 모아, 세계마다 `updateRankings(state, 다른 세계 줄)`. 화면에는 시즌 전체 순위(사람만)와 내 세계 순위(봇 포함, 떠돌이 표시).
- 마지막 장날 뒤: 모든 세계를 다 돌린 다음 `settleSeason(state, 다른 세계 줄)`. 인장과 칭호는 시즌 전체 순위로, 증서는 `certificates` 표에 옮긴다.
- 명예의 전당(시즌마다 부문 1위, 사람만) 표를 채운다.
- **"개척 상인"**(handoff 6번): 비공개 테스트 시즌을 결산할 때, 그 시즌에 하루라도 들어온 사람 모두에게 테스터 전용 인장. 그림이 없으면 등급 색 메달.
- "시험 시즌"으로 표시된 시즌은 결산 화면은 보여 주되 시즌 전체 랭킹·인장·칭호·명예의 전당을 남기지 않는다. 예행연습 시즌은 비공개 테스트 전에 세계와 증서 기록을 지운다.

## 13. 봇으로 서버 시즌 한 번, 비공개 테스트

- 서버에 봇 12명 세계 둘을 열어 시즌을 끝까지 돌린다(시간을 빠르게 하는 시험 모드). 확인할 것: 장날이 빠지지 않는다, 같은 시드 세계 둘의 지도·사건 일정·얼굴이 같다, 시즌 전체 랭킹(봇 빼고)과 결산, 상태 크기와 함수 시간, 견습 세계에서 졸업해 들어오기.
- **예행연습**(handoff 2번): 봇 시즌 다음, **지인 2~3명과 3~4일**을 실제 시간으로(빠르게 하지 않는다). 볼 것: 로그인과 초대 코드, 시작 화면, 견습 → 졸업 → 공유 세계 들어가기, 장날이 빠지지 않는지, "자리를 비운 사이", 아이폰 사파리에서 끊겼다 다시 이어지기. 나온 문제를 고친 뒤 예행연습 세계와 증서·인장 기록을 지운다.
- 그다음 비공개 테스트: 세계 2개 × 10~15명, 시즌 1번(답 107). 사람이 모자란 세계는 봇으로 12명까지(답 112). 시즌 중에는 시뮬 규칙과 숫자를 바꾸지 않는다(3번).
- **아이폰 확인 목록**에 더한다: 홈 화면에서 열었을 때 노치·홈 바가 가리지 않는지.
- **첫 5일 기록(답 120 가·라)**: 사람마다 시작 마을 묶음(도시에서 시작 / 도시까지 1·2·3·4일 이상), 첫 5일 순자산 변화(하루 값)와 판 이익(하루 값), 신문을 샀는지, 첫 구매 날. 세계마다 "보통 사람(사람 전체의 가운데)이 마이너스인가". 시작 마을 비교는 판 이익으로, 순자산도 함께 적는다. 결과를 보고 시작 마을 규칙(120 나)을 기획에서 정한다.
- **사람마다 더 기록할 것**(handoff 4번): 시작 화면에 걸린 시간, 견습 시작부터 졸업까지(실제 시간), 졸업부터 첫 거래 체결까지, 날마다 들어온 횟수와 머문 시간(대략), 마지막으로 들어온 날, 신문을 산 날 수, 소문 적기 / 흘려듣기 수, 예약 주문 수, 두 번째 행렬을 꾸렸는지, 말을 샀는지, 짐꾼·일꾼을 고용했는지, 독점(답 92, **사람 기준**도, 답 133). 시즌 끝에 12번 기록 표로.
- **로컬 측정 때 함께 적을 것**: 독점이 늘어난 세계 다섯의 마을·물품·사람(보통 사람 / 장사꾼 봇 / 원정꾼)(답 133, 고치지 않음). 봄 구휼 큰 주문이 채워지는지(낸 사람, 팔린 양)(답 127 측정).

## 하지 않는 것

원정 다시 보기(보류), 튜토리얼(기획자가 정함), 은행·소량 즉시 거래·길드 의뢰(보류), 채팅, 웹 푸시와 애플 로그인(앱 출시 때), 앱스토어 출시(Capacitor), 시작 마을 규칙(답 120 나, 비공개 테스트 숫자를 본 뒤), 새 세계 따라잡기(시즌 중간에 모두 차면 다음 시즌 대기), 계정 지우기 화면(운영자가 지운다), 의견에 사진 첨부, 장날 결과 하나씩 되돌리기.
